# java-lotto-precourse

## ✅ 기능 목록

- [ ] 입력
    - [x] 로또 구입 금액을 입력 받는다.
    - [x] 로또 금액은 1,000원이며 이를 통해 구입 가능한 로또 개수를 계산한다.
    - [x] 구입한 로또 개수만큼 1~45 사이의 숫자 6개로 이루어진 로또를 발급한다.
    - [ ] 당첨 번호와 보너스 번호를 입력 받는다.
    - [ ] 당첨 번호와 보너스 번호는 1~45 사이의 숫자여야 한다.
    - [ ] 당첨 번호는 중복된 숫자가 없어야 한다.
- [ ] 출력
    - [ ] 당첨 통계와 수익률을 출력한다.
- [ ] 예외 처리
    - [x] 로또 번호 입력 시 숫자가 아닌 값을 입력할 경우 예외를 처리한다.
    - [ ] 로또 번호 입력 시 1~45 범위를 벗어난 숫자를 입력할 경우 예외를 처리한다.
    - [ ] 로또 번호 입력 시 중복된 숫자를 입력할 경우 예외를 처리한다.

## 🔄 실행 흐름

1. **프로그램이 "구입 금액을 입력해 주세요." 메시지를 출력한다.**
2. **프로그램이 구입 금액에 해당하는 로또를 발급하고, 발급된 로또를 출력한다.**
3. **사용자가 구입 금액을 입력한다.**
4. **프로그램이 "당첨 번호를 입력해 주세요." 메시지를 출력한다.**
5. **사용자가 당첨 번호를 입력한다.**
6. **프로그램이 "보너스 번호를 입력해 주세요." 메시지를 출력한다.**
7. **사용자가 보너스 번호를 입력한다.**
8. **프로그램이 당첨 통계와 수익률을 출력한다.**

## 💻 프로그래밍 요구 사항

- JDK 21 버전에서 실행 가능해야 한다.
- `Application.main()`에서 프로그램을 시작한다.
- `build.gradle` 파일은 변경하지 않는다.
- `camp.nextstep.edu.missionutils` 라이브러리 외 외부 라이브러리를 사용하지 않는다.
- `System.exit()`를 호출하지 않는다.
- 제공된 파일 및 패키지 구조를 변경하지 않는다.
- Google Java Style Guide를 준수하여 코드를 작성한다.
- indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다. 2까지만 허용한다.
- 3항 연산자를 쓰지 않는다
- 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- JUnit 5와 AssertJ를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다.
- 함수(또는 메서드)의 길이가 15라인을 넘어가지 않도록 구현한다.
- else 예약어를 쓰지 않는다.
- Java Enum을 적용하여 프로그램을 구현한다.
- 구현한 기능에 대한 단위 테스트를 작성한다. 단, UI(System.out, System.in, Scanner) 로직은 제외한다.

## ✍️ 커밋 메시지 규칙

- AngularJS Git Commit Message Conventions를 따른다.

- **커밋 메시지 구조**

  ```
  type: subject

  body (optional)

  footer (optional)
  ```

- **Type 종류**

    - `feat`: 새로운 기능 추가
    - `fix`: 버그 수정
    - `docs`: 문서 수정
    - `style`: 코드 포맷팅, 세미콜론 누락 등 (코드 변경이 없는 경우)
    - `refactor`: 코드 리팩토링
    - `test`: 테스트 코드 추가/수정
    - `chore`: 빌드 업무 수정, 패키지 매니저 수정 등

- **예시**

  ```
  feat: 쉼표 구분자로 숫자 덧셈 기능 구현
  ```
